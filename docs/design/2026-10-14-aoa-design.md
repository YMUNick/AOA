# AOA 面試即時翻譯輔助工具：設計提案

日期：2026-10-14（Asia/Singapore）
狀態：使用者已確認功能與科技感配色，並於 2026-10-14 授權開始工程及 GitHub 部署。本文件保留設計依據；實作狀態及驗證限制以 README 和實作紀錄為準。

實作取捨：第一版提供 OpenAI／Gemini 個人金鑰模式，以及可自行部署的 OpenAI 安全代理；回答一次完成後顯示，等待時可取消。前端可以獨立部署到 Pages，代理需另外設定 Cloudflare 帳戶與秘密。這些設定不能因前端上線而視為完成。

## 1. 目標與已確認需求

以 GitHub Pages 提供個人面試輔助網頁。使用者已確認聲音來自「麥克風收到的現場對話」。點選開始後持續產生英文字幕與繁體中文翻譯；隨時圈選內容，手動要求 AI 產生回答。首頁能設定連線、模型、個人背景及費用預算。

第一版以新版桌面 Chrome 為主要支援環境，預設回答為「可口述的英文＋繁體中文重點」。手機提供閱讀／貼上文字的降級流程；不承諾手機支援同樣的語音與本機翻譯功能。

不在第一版加入：Teams／Zoom 系統音訊、多語輸入、自動辨識面試官身分、音訊錄音儲存、履歷檔案解析、帳號管理、付款系統或自動代替使用者發言。單一麥克風也會收到使用者自己的聲音，字幕不標示未經確認的說話者。

## 2. 三種做法與推薦

| 方案 | 特點 | 判斷 |
|---|---|---|
| A. Pages＋瀏覽器能力＋小型 API 代理 | 本機翻譯優先；AI 金鑰放代理；有驗證與用量保護 | **推薦正式使用**，兼顧費用與金鑰管理 |
| B. 全靜態 Pages＋每次自行輸入 API key | 不需要架設代理；只適合個人自用與支援瀏覽器直連的 provider | 備選；記憶體中的金鑰仍可被頁面程式讀取，不能宣稱隱藏金鑰 |
| C. 雲端語音辨識＋雲端翻譯 | 較少依賴瀏覽器辨識服務，增加音訊 API 費及串流整合 | 後續在實測顯示 A 不夠可靠時再加入 |

GitHub Pages 是靜態託管，不能執行後端或保管伺服器秘密。推薦架構把前端留在 Pages，另以 Cloudflare Worker 類型的輕量服務代理模型請求。[GitHub 官方說明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

第一個實作 provider 建議 **OpenAI API 的低成本文字模型**；目前查核為 `gpt-6-luna`。Claude、Gemini 採同一個介面擴充，不在第一版畫面提供尚未能用的選項。「Codex API」在本專案指 OpenAI 模型 API，不使用寫程式專用模型；API 費用和 ChatGPT／Codex 訂閱分開。

### 首頁

1. 簡短標題與「英文 → 繁體中文」固定方向。
2. 收音來源顯示麥克風，提供測試流程及瀏覽器／權限狀態；第一版使用系統預設麥克風，避免提供無法套用到辨識服務的裝置選單。
3. 翻譯模式：本機優先。顯示可用、需要下載、準備中或不可用；先完成語言包準備，再進入面試。
4. AI 連線：服務網址、存取碼、已啟用模型與「測試連線」。測試分成不計模型費的連線檢查及有標示的短回答測試。
5. 個人背景：應徵職位、實際經歷與希望強調的能力；可留空。預設不儲存，使用者明確選擇才留在本機。
6. 一小時估算：預期回答次數預設 20、回答長度預設精簡、預算預設 US$0.50。列出估算依據、使用單價及更新日期。
7. 主要按鈕「開始監聽」。AI 未連線仍可進入本機字幕／翻譯；AI 回答按鈕顯示設定入口。

### 監聽工作台

- 畫面持續顯示監聽狀態、時間、翻譯模式、估算累計費用，以及暫停／結束；桌面把時間、費用與主要控制放在底部控制列。
- 左側約 60%：每段英文在上、繁中在下；未定稿字幕獨立顯示，不覆寫已完成段落。
- 右側約 40%：選取內容快照、回答長度、產生／取消、英文建議回答與中文重點。
- 拖曳圈選後顯示「用這段產生回答」；每段也有可用鍵盤點選的替代按鈕。只有按鈕被觸發才送 AI 請求。
- 圈選或閱讀舊段落時暫停自動捲動，提供「回到最新」。新字幕不能清除選取內容或改變正在回答的問題。
- 沒有提供真實經歷時，回答以可替換框架或追問呈現，不編造任職公司、成果、數字或證照。
- 結束後可匯出英中逐字稿與回答文字，預設不保留音訊、不上傳整份逐字稿。

### 響應式與無障礙

桌面雙欄；窄螢幕切換「字幕／回答」分頁，監聽狀態仍可見。正文至少 16px、字幕約 20px，觸控目標至少 44px，文字對比至少 4.5:1。所有欄位有可見標籤、清楚焦點與鍵盤操作；不只用顏色表示狀態。讀屏只公告狀態變化與定稿內容，不逐字朗讀每次 interim 更新。遵循減少動態效果設定。

## 4. 收音與翻譯流程

```text
麥克風
  → 瀏覽器英文語音辨識
  → 英文未定稿預覽／定稿段落
  → Chrome 本機繁中翻譯（可用時）
     或 使用者已允許的付費文字翻譯
  → 使用者圈選內容＋少量上下文＋個人背景
  → 有驗證的 API 代理 → AI 英文回答＋中文提示
```

瀏覽器辨識採 `SpeechRecognition || webkitSpeechRecognition`、`en-US`、continuous 與 interim results。它可能使用瀏覽器廠商的雲端服務，不能宣稱全程離線；本機語音辨識僅在能力檢查及語言包準備成功後使用。沒有官方一小時不中斷的保證。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)

翻譯優先 `Translator`，檢查 `en → zh-Hant` 的 availability；需下載時顯示進度。此能力針對支援的桌面瀏覽器，不能只用瀏覽器品牌判斷。付費備援須在首頁清楚啟用；未啟用時保留英文並提示翻譯不可用，不暗中開始計費。[Chrome 官方文件](https://developer.chrome.com/docs/ai/translator-api)

定稿字幕以 session ID、recognizer generation、result index 去重。翻譯佇列用穩定段落 ID 回填，允許不同請求完成時間不同。付費翻譯只處理新定稿片段，短暫合併相鄰片段，避免每個字重送；不使用延遲批次計價服務。延遲需實測，不宣稱固定秒數。

## 5. 前後端分工

建議前端 React＋TypeScript＋Vite，產出靜態資產；Pages base path 設為 `/AOA/`，以單頁狀態或 hash 導航避免重新整理路由 404。這是建議技術選型，repo 目前沒有既有框架。

前端模組：語音辨識控制、字幕資料、翻譯佇列、選取快照、AI 回答、用量計算、首頁設定。把瀏覽器能力與模型供應商包成介面，避免畫面直接依賴某一家 API。

代理最小介面：

| 路徑 | 工作 |
|---|---|
| `POST /session` | 驗證私人存取碼，建立短效會話憑證；限制登入嘗試 |
| `GET /capabilities` | 回傳已啟用模型、單價日期及支援功能；不洩露秘密 |
| `POST /translate` | 接收新定稿片段，限制文字長度、同時請求數與輸出上限 |
| `POST /answer` | 接收圈選快照、有限上下文與背景；逐步回傳回答、usage 或錯誤 |
| `GET /usage` | 回傳該使用者的累計用量、預留用量與預算狀態 |

每個生成請求帶唯一 request ID；重送不能無限制重複扣款。provider key 放伺服器 secrets，不放前端環境變數、repo、網址或紀錄。只允許既定模型與既定上游服務；CORS 白名單不等於身分驗證。代理驗證、限制大小、限制輸出並限流；使用具一致性的用量狀態管理（例如 Durable Object），不能只靠瀏覽器計數或容易重置的 session 預算。重新建立 session 不重置使用者總額。

供應商回應文字當作資料顯示，不直接執行 HTML。逐字稿與個人背景以明確資料欄位傳入，不當作高優先指令。預設不記錄原始音訊、完整提示、逐字稿或金鑰。[Gemini 金鑰指引](https://ai.google.dev/gemini-api/docs/api-key)、[OpenAI API 驗證](https://developers.openai.com/api/reference/overview)

## 6. 一小時費用估算

幣別均為美元。以下為 **2026-10-14 官方牌價與工程假設計算，不是實測帳單**。不套用 Batch／快取折扣，不依賴免費額度。不同 tokenizer、回答長度與 thinking tokens 都會影響實際用量。

估算條件：60 分鐘、約 9,000 英文單字（約 12k tokens）；20 次手動回答，每次約 1,500 輸入與 500 輸出 tokens。若使用雲端文字翻譯，另估 240–720 次短句請求、每次 200 tokens 的提示／有限前文、18k–30k 中文輸出。合計 90k–186k 輸入、28k–40k 輸出。費用餘裕採 20%，並非總額保證。

| 模型 | 輸入／1M tokens | 輸出／1M tokens | 本機翻譯＋20 次回答 | 雲端文字翻譯＋20 次回答 |
|---|---:|---:|---:|---:|
| OpenAI `gpt-6-luna` | $0.10 | $0.50 | 約 $0.01 | 約 $0.03–0.05 |
| Claude `claude-haiku-5-5` | $0.10 | $0.50 | 約 $0.01 | 約 $0.03–0.05 |
| Gemini `gemini-3.5-flash-lite` | $0.30 | $2.50 | 約 $0.04 | 約 $0.12–0.19 |

上述兩個情境價格均含 20% 餘裕。Claude 該牌價適用提示長度不超過 100k tokens；本專案應遠低於此值。翻譯關閉或最低化可關閉的推理；回覆思考用量亦須計費。實作時依模型能力驗證參數，不把某一家設定直接套用到其他家。

公式：`輸入 tokens × 輸入單價 / 1,000,000 ＋ 輸出（含計費思考）tokens × 輸出單價 / 1,000,000`。

例：OpenAI 本機翻譯情境是 `(30,000×0.10＋10,000×0.50)/1,000,000×1.2 = US$0.0096`。沒有呼叫回答時，本機翻譯路徑不產生模型 API 費。

來源：[OpenAI Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、[Claude Haiku](https://platform.claude.com/docs/en/models/haiku-5-5/overview)、[Gemini 價格](https://ai.google.dev/gemini-api/docs/pricing)。模型是否能在使用者帳戶使用，仍須連線測試確認；價格最低不代表已證實品質最好。

費用表**不含另外購買的語音 API、代理服務／狀態儲存、稅或匯差**。瀏覽器語音辨識在本方案沒有額外採購語音 API，但仍可能連接瀏覽器廠商服務。未來若改用 `gpt-live-transcribe`，按目前牌價音訊部分約另加 US$1.02／小時；不能把分段檔案辨識的便宜價格當成持續即時串流價格。[OpenAI 價格](https://developers.openai.com/api/docs/pricing)

小量代理可能落在免費額度，仍須計入驗證、串流及狀態儲存所用產品的限制；不承諾後端一定免費。Workers 付費方案有月基本費，不能當作每小時費率。[Cloudflare 價格](https://developers.cloudflare.com/workers/platform/pricing/)

## 7. Token 與預算控制

- 不把整場逐字稿反覆送到模型；字幕只送新句，回答只送圈選內容與有上限的上下文。
- 圈選最多約 1,000 字元；相鄰字幕與背景分配固定輸入預算，過長時顯示截取提示，保留使用者選取的核心問題。
- 預設精簡回答；前述 500 輸出 tokens 是估算目標，後端另設固定可計費輸出上限。避免不必要搜尋、工具呼叫與長推理。
- 翻譯佇列去重；只有暫時性錯誤可有限次重試，遵守 Retry-After，不重試驗證失敗。
- UI 分開顯示供應商 usage 的計算值與尚未結算的估算值。中斷且沒有 usage 的請求標示未確認，不能當成零費用；保留該請求的預留費用，待核對後才釋放。
- 每次呼叫前預留最大合理費用，完成後按 usage 核對；並行請求必須原子預留，避免一起穿越預算。
- 預算 80% 提醒；到 100% 停止新的付費請求，保留本機字幕／翻譯。這是本應用的用量防護，不是供應商整個帳戶的帳單硬上限；已送出的請求仍可能計費。

## 8. 狀態、錯誤與保留內容

監聽狀態：未開始 → 請求權限 → 監聽中 → 重新連線／暫停 → 結束。使用者按停止時先清除繼續監聽意圖與重試計時器，避免 onend 又把麥克風開回來。

麥克風拒絕、沒有輸入裝置、服務禁止：停止並提供修正文字；沒有說話：顯示等待；網路問題：有限次退避重連，超過次數顯示重試。AI 429／連線中斷不應中止麥克風。翻譯失敗保留英文，單段可重試；回答失敗保留選取問題與已輸出文字。切換 session 或停止後，忽略舊請求遲到結果。

## 9. 實作驗收標準

以下是預定驗證，不代表已通過：

1. 主要流程：首頁設定 → 監聽 → 英文定稿 → 繁中 → 圈選 → 英文回答／中文重點 → 結束匯出。
2. 多次 interim／final 事件不重複字幕；翻譯亂序返回仍對應正確段落；圈選不被新字幕移走。
3. 使用者停止後不自動重啟；權限拒絕不無限重試；辨識失敗仍保留已完成字幕。
4. 沒有 AI key 也能使用已就緒的本機字幕／翻譯；本機翻譯不可用時不擅自啟用付費服務。
5. 輸入大小、驗證、限流、預算預留、usage 缺失與 request ID 重送測試；build 檢查不含任何 provider key。
6. 375px、768px、1440px 排版及鍵盤操作；Pages `/AOA/` 路徑與重新整理檢查。
7. 在使用者實際 Chrome、麥克風與網路環境進行 60 分鐘演練，量測漏字／重複、斷線、恢復、延遲與實際費用，通過後才宣稱適合長時間面試。

## 10. 設計確認後的交付順序

先建立首頁與字幕工作台、瀏覽器能力檢查和示範模式；再接真實麥克風／本機翻譯；再接單一 provider 的驗證代理、按需回答與預算；最後做 Pages 部署設定和端到端驗證。Cloudflare 帳戶／代理部署及 provider key 需在真正啟用時設定，不能把設計稿視為已部署的服務。
